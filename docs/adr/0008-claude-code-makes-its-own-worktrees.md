# Claude Code makes its own worktrees, and one setup script finishes every worktree

The Template no longer routes Claude Code's worktree tool through `template/scripts/new-worktree.sh`. Claude Code makes its own worktrees, and removes one whose agent changed nothing. A session that has committed leaves its worktree before it acts on the primary checkout (see Consequences). `new-worktree.sh` stays for Codex, Copilot and OpenCode, which have no worktree tool. In every CLI, the first command in a worktree is `node scripts/setup-worktree.mjs`. That one script names the branch `agent/<issue id>-<slug>`, sets the commit identity, copies the installed skills, renders the briefing and runs `npm ci`. `guard-unprovisioned-worktree.mjs` refuses every other command in a worktree until the branch says the setup ran. The two hooks `worktree-create.mjs` and `worktree-remove.mjs` are deleted. The operator chose this, as option B of three, and approved the work on 2026-11-10.

The WorktreeCreate hook existed so that one script made every worktree. It bought four things, and by Claude Code 2.1.321 each was worth less than it cost:

| What the hook bought | What Claude Code does by itself | What the hook cost |
|---|---|---|
| A base of `origin/main`, with no upstream | Cuts from origin's default branch with no upstream, and fetches when its last fetch is over a day old | Little. The setup script now fetches and fast-forwards a fresh worktree. |
| A branch named `agent/<name>` | Names the branch `worktree-<name>` | A subagent's name is `agent-<agent id>`, so a lane's branch was `agent/agent-<id>` and named no issue. |
| A briefing, with ports and a deadline | Nothing: no hook runs after it makes a worktree | Nothing. The setup script renders the same briefing. |
| The installed skills, copied | Copies files a `.worktreeinclude` names | Claude Code skips `.worktreeinclude` when a WorktreeCreate hook is set. |

The larger cost was cleanup. Claude Code removes a worktree it made once its agent finishes with nothing changed. It does not remove one that a hook made. In the Target `spec-storming`, about 50 reviewer worktrees were left behind that way in two days.

## Considered Options

- **A. Keep both hooks, and add the lock and the identity to the script.** Rejected: reviewer worktrees would still pile up, because nothing removes a hook-made subagent worktree.
- **C. Stop using Claude Code's worktree isolation, so lanes work in script-made worktrees.** Rejected: nothing would then stop a lane's edit from landing in the primary checkout or in a sibling's worktree.
- **Keep the WorktreeRemove hook alone.** Rejected: with no WorktreeCreate hook set, Claude Code 2.1.322 does not call it (E2).
- **Lock a worktree in the setup script.** Rejected: Claude Code's own removal would then fail on the lock, and unchanged worktrees would pile up again.
- **Copy the installed skills with `.worktreeinclude`.** Not chosen: the setup script copies them for every CLI, so one mechanism serves all four.
- **Rename the branch with `git branch -m`.** Rejected: it takes the lock of the one `.git/config` every worktree shares, and with that lock held it renames the branch and then exits with an error. The setup script moves the ref and HEAD with plumbing, which writes no config.

## Consequences

- **Two ways to make a worktree exist again**, which is what the hook was written to stop. Everything a session relies on is set by the one setup script, so the two ways differ only in who runs `git worktree add`.
- **A lane that changes nothing leaves an empty branch.** Claude Code removes the unchanged worktree and keeps the renamed branch `agent/<name>`. The setup script replaces such a branch the next time that name is used, when the branch holds no commit `origin/main` lacks.
- **The guard's signal is the branch name.** A setup that renamed the branch and then failed, at the briefing or at `npm ci`, leaves a worktree the guard reads as set up. The setup's exit status and its message are what say so.
- **Claude Code's worktrees are not locked by this repository.** Claude Code locks a `claude --worktree` session's worktree itself. A worktree it keeps after a subagent's commit carries no lock, so a `git worktree prune` in a dev container can still take its record. The text guard refuses a prune a session types, and the image sets `gc.worktreePruneExpire` to `never`.
- **A session leaves its worktree before it acts on the primary checkout.** Inside a worktree it made, Claude Code refuses a git command aimed at another checkout, and `ExitWorktree` refuses action `remove` once the branch holds a commit (E6). So both finishes begin with `ExitWorktree`, action `keep`, which puts the session back in the primary checkout. A `via-merge` finish then runs `git merge --ff-only <branch>` there. After a merged pull request, the session runs `git worktree remove <path>` there. The briefing's merge sentence is now a substitution each CLI fills, `{{CLI_VIA_MERGE}}`, because Codex, Copilot and OpenCode hold no session inside a worktree and still use `git -C <primary>`.
- **A `via-merge` finish leaves its worktree on disk.** No version of the Template removed it, and this change does not start to.
- **The remove hook's workaround is gone.** That hook existed because `git worktree remove` failed inside the dev container with "Device or resource busy", last verified on Claude Code 2.1.241. After a merged pull request the session now types that command itself, from the primary checkout. Whether it fails there is not known (see Evidence). If it does, the worktree stays and the session says so.
- **A headless `claude -p --worktree` run leaves its lock behind.** The process that held it is gone, and nothing here clears it but `git worktree unlock`.
- **Claude Code's isolation refusals are unchanged.** They apply to every worktree Claude Code enters, hook-made or its own.
- **Fan-out in Codex, Copilot and OpenCode is unverified.** Their dispatcher prompt now says to make each lane's worktree with the script and to start a session in it. No trial checked that those CLIs can start one.

## Evidence

The trials ran on the maintainer's macOS arm64 laptop on 2026-11-09 and 2026-11-10, as headless Claude Code sessions in scratch repositories. Each verdict was read from git's state afterwards or from the session's own transcript.

- **E1.** Claude Code 2.1.321: a subagent worktree that held only ignored files was removed, with its branch, when the agent finished. A branch rename inside a worktree survived, and the worktree was kept after a commit. The tool result named the branch as it was before the rename.
- **E2.** Claude Code 2.1.322, in a repository whose settings registered only a WorktreeRemove hook: the hook's log stayed empty after a subagent's unchanged worktree was removed, and after `ExitWorktree` with action `remove`. Both removals succeeded. In both, and in the same runs without the hook, the renamed `agent/<name>` branch was left behind.
- **E3.** With `.git/config.lock` held, `git branch -m` renamed the branch and exited with "branch is renamed, but update of config-file failed". `git update-ref` and `git symbolic-ref` moved the same branch with no error.
- **E4.** Claude Code 2.1.322, in a scratch Target rendered from this change, whose primary checkout mise trusted. In a subagent's fresh worktree the guard refused `pwd` and `git status --short`, and each refusal named the setup command. `node scripts/setup-worktree.mjs zz-1-probe --no-install` then ran under Claude Code's isolation. It renamed the branch to `agent/zz-1-probe`, set the bot's identity and rendered the briefing, and a commit made there was authored by the bot. In a worktree made with `EnterWorktree`, the setup took the name from the directory, and `ExitWorktree` with action `remove` removed the worktree, which held no commit. Claude Code removed the worktree of a lane that changed nothing, and left its empty branch. A second lane under the same name replaced that branch and committed on it. `npm ci` was not exercised: every run passed `--no-install`.
- **E5.** `mise run worktree:selftest` holds the setup script in a scratch repository, in worktrees made as Claude Code makes them. It renames the branch with `.git/config.lock` held. It brings a worktree cut behind `origin/main` up to it, and the same script with that step taken out leaves the worktree behind. It refuses a worktree cut from a commit `origin/main` does not hold, a subagent's worktree given no name, and the primary checkout. It replaces an empty `agent/<name>` branch and refuses one that holds work.
- **E6.** The first credentialed Work run on this change, on 2026-11-10 with Claude Code 2.1.302, failed. The session entered its worktree, committed, passed the gates and its review, and then ran the briefing's `git -C <primary> branch --show-current`. Claude Code refused it, and the session stopped with the issue open, as the briefing asks of a refused command. The last passing Work run, on 2026-10-17, had not entered a worktree at all: its session ran the worktree script and changed directory, so nothing held it. Trials on 2.1.302 and 2.1.322 then gave the same results on both. Inside the entered worktree, `git -C <primary> branch --show-current` and `cd <primary> && git branch --show-current` were refused. `ExitWorktree` with action `remove` was refused once the branch held a commit, with a message that tells the session to confirm with the user. After `ExitWorktree` with action `keep`, the session was in the primary checkout, where `git merge --ff-only agent/<name>`, `git worktree remove <path>` and `git branch -d agent/<name>` each passed. The `open-pr` skill's watcher loop and `gh pr checks --watch` passed inside the worktree.
- **E7.** With the corrected text, a session on each version was given a worktree with one commit and told only to finish as its briefing's step 4 says, with `via-merge`. Each left the worktree, checked the branch and fast-forwarded `main`. A second session on each version was told only to clean up as the `open-pr` skill's last step says. Each left the worktree and removed it, and the branch stayed.
- **Not verified.** A removal inside the dev container, by Claude Code or by `git worktree remove`. The trial needs a model credential in the container. The Template test's Work run uses `via-merge`, which removes nothing, so it does not cover this.
