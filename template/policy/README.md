# `tools/policy/`

**The workflow's policy: every constant a prompt or a tool reads, each under a key with its reason
beside it, in one record per kind of key.** The records split the constants by who may change them
and who reads them (`docs/decisions.md` § D-27). Every record is a hand-authored decision record
(`CLAUDE.md` § Three kinds of file, and never a fourth): it opens with `describes`,
`whyThisFileExists`, `gatedBy`, `whatItDoesNOTDo` and `provenance`, and gives each constant a
`<key>Means` sibling.

A reader asks for a key, never for a record: `tools/lib/policy.ts` merges every record into one
object and refuses a key two records define, and `node tools/lib/policy.ts <key>...` prints keys for
a prompt or a workflow's command. `check:policy` refuses a record without its header, a constant
without its `Means`, a key in two records, and a record this table does not name. What each value
must be is held by the gates its record's `gatedBy` names.

Each record's header is the authority on it. Where a row here and a record disagree, the record wins
and the row is corrected; where a record and the register disagree, the register wins.

| Record | Who merges a change | What it holds |
|---|---|---|
| `vocabulary.json` | GitHub's auto-merge; a person for a key `prReviewHighRiskJsonKeys` names | The spellings every stage of the workflow agrees on. For a change: the label on its epic and tasks (`specChangeLabel`) and each capability's ID prefix (`specIdPrefixes`). For the tracker: the three label vocabularies a run leaves there and the instant from which a found issue must carry a found-at label, the type and priority every issue is filed with (`issueTypes`, `issuePriorities`), the command that files a found issue with them, and the prefix of the label that counts how many runs have found an issue (`seenLabelPrefix`). For a test: the hash length and layers of its trace line, the layers that count toward a scenario's obligation, and the key of the trailer that records an architect's decision to remove, skip or weaken one. `openspec:check`, `calculator:test`, `trace:check`, `tests:inventory:check` and `beads:check` hold them. |
| `agent-workflows.json` | GitHub's auto-merge; a person for a key `prReviewHighRiskJsonKeys` names | The sizes and bounds of the agent workflows: the build workflow's review, red run and independent test-builder (`buildReview*`, `buildRedFirstKinds`, `buildIndependentKinds`, `independent*`, `architectRunLayers`, `buildArchitectMaxRounds`); the scenario trace at verify (`verifyTrace*`); the bounds on a workflow a session writes itself (`session*`); and how many fixes that each failed a session makes against one failure before it stops and reports (`rootCauseMaxFixes`, which the `root-cause` skill reads). The `promptReview*` keys, kept together because the reviewer reads them by prefix, are the batched prompt review's markers, thresholds and skeptics, the heading of an analysis's loaded prompts and the label of its session line, and its TypeSafe match's. They also hold the load count's window, floor, cut-off, not-viable share and table of prompts no analysed run loads, and the fix-recurrence rate's floor and not-viable share. `workflows:selftest` holds the ones a workflow script reads, `prompt-runs:selftest` the markers, the due check, the load count's and the fix-recurrence rate's, and `prompt-review:match:selftest` the match's. |
| `pr-review.json` | a person: `prReviewHighRiskPaths` names it | What the pull-request reviewer reviews by (`prReview*`): the shape of an issue's ID, the login its review is submitted as and the check auto-merge also waits for, and the rubric the branch reviewer holds each path to. Also the high-risk floor, which is the whole decision since `docs/decisions.md` § D-37, the merge method, how often a session's `scripts/pr-review.mjs wait` reads a pull request, and the Actions secret holding the agents' App key with the one workflow and environment that may read it (`prReviewAppKey*`). `pr-review:check` holds them, and refuses a floor that does not cover this record, `prompt-budgets.json`, the loader, `tools/lib/policy.ts`, the git helper the reviewer's job imports, every workflow, the branch reviewer and the `open-pr` skill that runs it, or `tasks.toml`. Nor may the floor miss both guards and the helper they import, a committed `node_modules`, a Stryker config, npm's shrinkwrap and its `.npmrc`, or the toolchain's config and lock files and the dev container's Dockerfile. It refuses too a floor that misses a file a gate `prReviewFloorTasks` lists runs or imports, or a policy key such a file names, which it derives (`docs/decisions.md` § D-38). And it refuses a `verify.yml` that runs such a gate after anything off the floor in its job, or beside one `prReviewFloorProductTasks` lists (`docs/decisions.md` § D-55). |
| `prompt-budgets.json` | a person: `prReviewHighRiskPaths` names it | `promptWordBudgets`, one table keyed by each prompt's path, each row the most words the prompt may hold and the reason for the figure. `check:prompts` refuses a prompt over its budget or with no row, a row that names no prompt, and a row with no reason. |
| `tool-settings.json` | GitHub's auto-merge; a person for a key `prReviewHighRiskJsonKeys` names | The settings of single tools: the coverage and mutation gate (`threshold*`, `mutationCommands`), the worktree sweep (`worktreeGc*`), the git hook runner's output (`gitHooksFailedOutputBytes`), the fresh run's deadline (`freshRunDeadlineSeconds`), the platforms the toolchain's lockfile covers (`toolchainLockPlatforms`), the local code graph (`graphify*`), the co-change map (`coupling*`), the advisory citation-support check (`typesafeModel`, `citationSupport*`), the agents' GitHub App, its installation and when a kept token of it is replaced (`githubApp*`), and the Langfuse projects, endpoint, field groups, names and limits the prompt runs' figures read by (`langfuse*`). The harness reads six of them through `tools/harness/harness.config.json`, which keeps its own settings beside it (`docs/decisions.md` § D-26). |
